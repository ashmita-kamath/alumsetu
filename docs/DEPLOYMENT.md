# Deployment

| Part | Host | Address |
|---|---|---|
| Website (React) | Vercel | add the Vercel link here |
| API (Express) | Render (free, Singapore) | https://alumsetu-api.onrender.com/api |
| Database (PostgreSQL) | Neon | private |
| File uploads | Cloudinary | private |

Step-by-step setup of the API is in `docs/DEPLOY-SERVER.md`.

## Production secrets
Secrets are stored only in the hosting dashboards, never in the repo or in chat.

| Variable | Where | What it is |
|---|---|---|
| `DATABASE_URL` | Render | Neon connection string |
| `JWT_SECRET` | Render | Generated by Render (`render.yaml`), signs login tokens |
| `CLOUDINARY_URL` | Render | `cloudinary://API_KEY:API_SECRET@CLOUD_NAME` from the Cloudinary dashboard |
| `CLIENT_URL` | Render | The Vercel address. Only this website may call the API from a browser |
| `NODE_ENV` | Render | `production` (set by `render.yaml`) |
| `VITE_API_URL` | Vercel | `https://alumsetu-api.onrender.com/api` |

Safety checks built into the server:
- It will not start in production without `DATABASE_URL` or a strong `JWT_SECRET`.
- The test-only `X-Dev-User-Id` header is ignored in production.
- Passwords are hashed with bcrypt; admin accounts can only be created from the command line.

## Private files
- **Verification documents** (degree, ID card) are uploaded to Cloudinary as `authenticated` files.
  Their plain link does not open. Only an admin, from the verification queue, gets a link that
  expires after 10 minutes.
- **Resumes** are normal files, because the alumnus who posted the job needs to open them.
- Files are checked by their first bytes, not their name: only PDF, JPG and PNG, up to 5 MB.

## Smoke test
After every deploy, run the automated smoke test from `server/` on a laptop:
```
API_URL=https://alumsetu-api.onrender.com/api SITE_URL=https://<vercel-link> DEMO_PASSWORD='...' npm run smoke-test
```
It runs the 6 flows from the roadmap against the live server with the demo accounts and then
deletes what it created (anything titled `[smoke]`):

1. Server is up, database connected, all three demo accounts log in, CORS allows only our website.
2. A verification document uploads as a private file (its plain link is blocked); a resume uploads.
3. Directory search, AI mentor suggestions, mentorship request → accepted → completed.
4. Event created, student registers and cancels.
5. Job posted, student applies, alumnus shortlists.
6. Forum post reported and hidden by an admin; hidden from users, visible to admins.

It ends with `Result: N passed, 0 failed`. Upload checks are skipped if `CLOUDINARY_URL` is missing.

## Before the demo
- The free Render server sleeps after 15 minutes without traffic and takes about a minute to wake.
  Open the site (or run the smoke test) a few minutes before presenting.
