# Deploying the API to Render (Phase 7, server)

The API runs on **Render**, the database on **Neon**, and the website on **Vercel**.
`render.yaml` in the repo root holds the Render settings.

## 1. Create the service (once)
1. Sign in at render.com with GitHub.
2. **New → Blueprint** → choose `ashmita-kamath/alumsetu` → **Apply**.
3. Render asks for three values:
   - `DATABASE_URL`: the Neon connection string (Neon → Dashboard → Connection string).
   - `CLOUDINARY_URL`: from the Cloudinary dashboard.
   - `CLIENT_URL`: the Vercel website address, e.g. `https://alumsetu.vercel.app,https://alumsetu-*.vercel.app`.
     If the website isn't deployed yet, leave it empty for now (all sites are allowed) and fill it in later.
4. `JWT_SECRET` is generated by Render automatically. `NODE_ENV` is set to `production`.
5. Wait for the deploy. Open `https://<your-service>.onrender.com/api/health`. It should show `"database":"connected"`.

## 2. Prepare the production database (once)
In the Neon SQL Editor, if not already done, run in this order:
`database/schema.sql` → `database/seed.sql` → `database/sample-data.sql` → `database/sample-content.sql`.
On an existing database, run `database/migrations/002_indexes.sql` instead of `schema.sql`.

## 3. Create the demo accounts
From `server/` on your laptop, with `DATABASE_URL` in `server/.env` pointing at Neon:
```
DEMO_PASSWORD='choose-a-long-password' npm run create-demo-users
```
This creates `demo.student@alumsetu.in`, `demo.alumni@alumsetu.in` (verified mentor) and
`demo.admin@alumsetu.in`. Running it again resets them. Share the password with the team privately.

## 4. Connect the website
In Vercel, set `VITE_API_URL=https://<your-service>.onrender.com/api` and redeploy.
Then put the Vercel address in Render's `CLIENT_URL` and save (Render redeploys by itself).

## Checks
- The server refuses to start in production without `DATABASE_URL` or a strong `JWT_SECRET`, and
  logs any other missing setting. Look at Render → Logs if a deploy fails.
- In production the test-only `X-Dev-User-Id` header is ignored, so only real logins work.
- The free plan sleeps after 15 minutes without traffic. The first request then takes about a minute,
  so open the site a few minutes before the demo.
- Desktop and mobile apps (Phase 8) are allowed by CORS automatically.
